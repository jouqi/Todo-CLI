# Todo CLI

一个使用 Python 编写的交互式命令行任务管理工具，支持任务增删、完成状态、优先级和本地 JSON 持久化。适合用于练习 Python 模块拆分、文件读写和单元测试。

## 已实现功能

- 添加任务，并指定 `high`、`medium` 或 `low` 优先级。
- 查看任务列表、当前序号、完成状态和优先级。
- 按序号完成或删除任务。
- 启动时读取本地任务，选择退出时保存到 JSON 文件。
- 使用 pytest 测试添加、完成和删除任务的正常及非法输入情况。

## 安装与运行

需要 Git 和 Python 3。程序本身只使用 Python 标准库，不需要安装第三方运行依赖；测试需要单独安装 pytest。

### 1. 获取代码

```bash
git clone https://github.com/jouqi/Todo-CLI.git
cd Todo-CLI
```

后续命令均在项目根目录执行。以下使用 `python`；如果你的系统使用 `python3`，请将命令中的 `python` 替换为 `python3`。

### 2. 创建虚拟环境（推荐）

```bash
python -m venv .venv
```

Windows PowerShell 激活：

```powershell
.\.venv\Scripts\Activate.ps1
```

macOS / Linux 激活：

```bash
source .venv/bin/activate
```

如果不激活环境，也可以直接使用虚拟环境中的解释器：Windows 为 `.\.venv\Scripts\python.exe`，macOS / Linux 为 `./.venv/bin/python`，替换下文的 `python` 即可。

### 3. 启动程序

```bash
python app.py
```

启动后会显示：

```text
==== Todo CLI ====
1. 查看任务
2. 添加任务
3. 删除任务
4. 完成任务
5. 退出
请选择：
```

## 使用示例

当前版本通过数字菜单交互。运行 `python app.py` 后，按提示输入以下内容：

| 操作 | 输入顺序 | 结果 |
| --- | --- | --- |
| 添加任务 | `2` → `学习 Python` → `high` | 添加一条未完成的高优先级任务 |
| 查看任务 | `1` | 显示当前任务列表 |
| 完成任务 | `4` → `1` | 将当前列表中的第 1 条任务标记为完成 |
| 删除任务 | `3` → `1` | 删除当前列表中的第 1 条任务 |
| 保存并退出 | `5` | 保存任务到 `my_tasks.json` 并结束程序 |

### 一次完整操作

以下示例从没有任务的数据状态开始；每次操作后程序会再次显示菜单，下面省略重复菜单。

```text
请选择：2
请输入要添加的任务：学习 Python
请输入等级：(high,medium,low)high
添加完成

请选择：1
1 [ ] [high] 学习 Python

请选择：4
1 [ ] [high] 学习 Python
你完成了哪个:1
设置完成

请选择：1
1 [X] [high] 学习 Python

请选择：5
数据已保存
```

再次启动并输入 `1`，会看到已保存的完成状态。若要练习删除，输入 `3`，再输入任务当前序号，最后输入 `5` 保存。

输入说明：

- 优先级只接受小写的 `high`、`medium`、`low`；当前按添加顺序显示，不按优先级排序。
- 任务序号从 `1` 开始，是当前列表位置；删除后，后面的任务会重新编号。
- `[ ]` 表示未完成，`[X]` 表示已完成。
- 空任务标题、非法优先级、非数字菜单输入和越界序号会得到提示。
- 当前删除和完成操作的重试循环没有取消选项，请先确认列表非空再进入；进入空列表的操作后只能中断程序，尚未保存的修改会丢失。

## 数据文件说明

数据文件使用相对路径，位于**启动程序时的当前工作目录**。建议始终先进入项目根目录再运行，避免在不同目录生成不同的任务文件。

| 文件 | 用途 |
| --- | --- |
| `my_tasks.json` | 持久保存任务；文件不存在时，程序从空列表开始 |
| `temp.json` | 保存过程中的临时文件；写入完成后，通过 `os.replace` 替换正式文件 |

选择菜单 `5` 时才会保存，添加、完成和删除操作只先修改内存。直接关闭终端、强制结束或按 Ctrl+C 不会触发当前的保存逻辑。正常保存成功时会显示“数据已保存”；若出现保存错误提示，请检查目录写入权限和磁盘状态。

保存后的数据示例（为便于阅读添加了缩进，实际文件可能为一行）：

```json
[
  {
    "title": "学习 Python",
    "done": true,
    "priority": "high"
  }
]
```

- `title`：任务标题，字符串。
- `done`：完成状态，布尔值。
- `priority`：优先级，取值为 `high`、`medium` 或 `low`。

`my_tasks.json` 已被 Git 忽略，不会随正常提交上传。程序使用 UTF-8 读写，并保留中文字符。

当前读取逻辑在 JSON 语法错误时返回空列表，不会提示损坏；随后选择退出会用当前任务覆盖原文件。遇到数据异常，应先备份原文件再排查。合法 JSON 的字段和整体结构尚未校验，请勿随意修改数据格式。

## 运行测试

在项目根目录、使用运行程序的同一个 Python 环境执行：

```bash
python -m pip install pytest
python -m pytest -q
```

只运行任务逻辑测试：

```bash
python -m pytest tests/test_todo.py -q
```

使用 `python -m pytest` 可以将当前项目根目录纳入模块查找路径；如果遇到 `ModuleNotFoundError: No module named 'todo'`，请确认当前目录包含 `todo.py`，并使用上面的命令。

现有 9 个测试覆盖添加成功、空标题、非法优先级，以及完成/删除时的有效序号、过大序号和零序号。测试使用内存中的任务列表，不会读写 `my_tasks.json`；交互流程和存储逻辑目前没有对应的自动化测试。

## 项目结构

| 路径 | 职责 |
| --- | --- |
| `app.py` | 程序入口：菜单、用户输入、启动加载和退出保存 |
| `todo.py` | 任务逻辑：查看、添加、完成、删除及序号检查 |
| `storage.py` | JSON 文件加载和临时文件替换保存 |
| `tests/test_todo.py` | 任务逻辑的 pytest 单元测试 |
| `README.md` | 项目说明和操作指南 |
| `.gitignore` | 忽略虚拟环境、缓存、编辑器配置和本地任务数据 |

`my_tasks.json` 与保存时使用的 `temp.json` 为运行生成文件，不属于仓库中的源代码。

## 最值得优先补上的改进

**安全处理损坏的数据文件，并为存储逻辑补充测试。**

当前程序会把语法错误的 JSON 当成空任务列表，退出时还可能覆盖原始文件。优先解决这一点，可以直接提高数据可靠性，也能补齐现有测试只覆盖任务逻辑的缺口。

建议的完成标准：

1. 区分“文件不存在”和“文件损坏”，损坏时显示明确提示并阻止静默覆盖原文件。
2. 校验读取结果是否为任务列表，以及每条任务的字段、类型和优先级是否合法。
3. 使用 pytest 的 `tmp_path` 在临时目录测试正常读写、缺失文件、损坏 JSON 和结构错误，确保不会改动真实任务文件。

以上为下一步建议，当前版本尚未实现。
